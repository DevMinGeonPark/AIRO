하단 섹션 구현을 마쳤습니다. 수정한 파일은 `src/components/landing/scroll-scenes.tsx`와 `src/app/landing.css` 두 개뿐이고, 빌드와 렌더 확인은 하지 않았으므로 시각적 승인은 스크린샷을 본 뒤에 판단하겠습니다.

**scroll-scenes.tsx 변경 요약**

- **FeatureStory**: 스티키 패널과 페이지네이션을 제거하고 세 챕터를 각각 다른 구도로 재구성했습니다. `.feature-article`, `.feature-copy` 셀렉터와 01→02→03 순서, 원문 카피는 그대로입니다. DOM 순서는 항상 카피 → 비주얼입니다.
- **01 대화 스레드**: 컨테이너 없이 페이지 위에 사용자·아이로 버블 4턴을 세로 타임라인에 걸었습니다. 첫 답변 아래 320px 결과 카드에 `JourneyMap`(Day 1, 앰비언트)이 붙어 핀이 떨어지고, 원문 "철학의 길 산책 · 14:00"과 "지도와 대화가 연결되는 여행" 문구가 남아 있습니다. 각 턴은 ScrollTrigger로 한 번 리빌되고, 타임라인 선은 스크롤에 맞춰 scaleY로 채워집니다.
- **02 지도 밴드**: 전폭(100vw) 종이 지도 밴드에 `./journey-map`에서 직접 가져온 `JourneyMap`을 기존 props만으로 사용합니다. 일정 패널의 Day 1·2·3 버튼은 `aria-pressed`이며 실제로 `day` 상태를 바꿔 엔진의 카메라 fit과 재생을 다시 시작합니다. 같은 날을 다시 누르면 재생을 반복합니다. 원문 "철학의 길 산책 14:00 / 골목 안 작은 카페 15:00 / 느긋하게, 교토"가 패널 안에 유지되고, 정류지 목록과 좌표 리드아웃은 `JOURNEYS` 실제 데이터입니다.
- **03 엽서**: 기존 day1·day2·day3 일러스트 세 장을 흰 테두리 엽서로 쓰고 맛집/예약/예산 라벨과 원문 설명을 유지했습니다. `feature-prep.webp`는 엽서 뒤 방사형 마스크 워시로 깔았습니다. 부채꼴 펼침은 뷰 진입 시 한 번, 모션 비활성 시엔 펼쳐진 상태로 고정됩니다. 스포트라이트는 마우스 전용, 매우 약하게 남겼습니다.
- **McpDiagram**: 허브-스포크를 "같은 여행, 두 창" 구성으로 바꿨습니다. 네 도구 버튼(`.mcp-node`, `aria-pressed`) → 요청 버블 → 연결선 위 점(`.beam-dot`) 이동과 중앙 아이로 허브 펄스 → 오른쪽 일정에 카페 행 삽입 → 답변 표시 순서의 GSAP 타임라인입니다. 도구를 바꾸거나 다시 누르면 재생되고, 두 창 헤더에 "미리보기" 배지가 붙습니다. `.mcp-connection-caption`은 `aria-live`로 유지했습니다. 화면 밖·탭 숨김·모션 비활성 시 정지하거나 완성 상태를 정적으로 보여줍니다.
- **CtaStage**: children 인터페이스 그대로입니다. 배경에 `JourneyMap`(Day 1)을 낮은 불투명도와 마스크로 깔고, `cta-journey.webp`는 우하단 260px 엽서 한 장으로 씁니다. 엽서만 스크롤 패럴랙스(transform)를 받습니다.
- **공통**: 지도 엔진은 마운트 시점에만 재생을 시작하므로 `useMapRun` 훅이 뷰 진입마다 key로 리마운트하고, 이탈 시 제자리에서 멈춥니다. 모든 애니메이션은 useGSAP(revertOnUpdate) 또는 motion이며 transform/opacity만 씁니다.

**landing.css 변경 요약**

- 1~100행의 히어로·네비·기존 프리뷰 규칙과 모션 규칙, 각 미디어쿼리의 히어로 부분은 그대로 두고, 옛 하단 규칙(features/mcp/cta/footer와 그 반응형)만 제거했습니다.
- EOF에 `.landing` 블록을 추가해 하단 섹션 전체 스타일을 `--lw-*` 접두 토큰으로 정의했습니다. 표면은 #FAF7F2 / #F4EFE6 / 흰색뿐이고 회색 프레임 패널은 없습니다.
- 타입 스케일은 데스크톱 h2 56 / h3 40 / 본문 16~18, 태블릿 h2 44 / h3 34, 모바일 h2 34 / h3 28 / 본문 14~15, 한글 자간 최대 -0.025em, 최소 12px(어트리뷰션 제외)입니다.
- 반응형 분기는 1200 / 1024~1199 / 1023 / 767에서 처리했고, 768~1023에서는 일정 패널이 밴드 아래로 내려가며 MCP 연결선은 세로로 바뀝니다.

**남은 시각적 리스크 (스크린샷으로 확인 필요)**

- **지도 바탕색 이음새**: 엔진 SVG의 배경 rect가 아직 #ECEFE9라면 밴드·CTA·미니맵에서 차가운 톤이 보일 수 있습니다. 밴드 안에서만 rect fill을 종이색으로 덮는 규칙을 넣었지만, `kyoto-base.svg`의 땅 색은 Codex의 지도 리스타일에 달려 있습니다.
- **컨테이너 폭 불일치**: Codex가 `.landing-container`를 1680px 등으로 바꾸면 하단 콘텐츠는 1240px에 맞춰 중앙 정렬되지만, 히어로 좌우 여백과 몇 px 어긋날 수 있습니다.
- **밴드 안 앰비언트 지도의 어트리뷰션과 핀 겹침**: 1024~1199px에서 지도를 220px 오른쪽으로 밀어 패널과 경로가 겹치지 않도록 했지만, 실제 fit 결과는 렌더로 확인해야 합니다.
- **CTA 지도와 헤드라인**: 지도를 섹션 우측 34%~110% 영역에 배치해 헤드라인과 경로가 분리되도록 했으나, 1440×900에서 경로 위치와 마스크 가장자리는 봐야 합니다.
- **MCP 연결선 길이**: 점 이동 거리는 마운트 시 `getBoundingClientRect`로 측정하므로 리사이즈 후에는 다음 재생(도구 클릭·재진입)까지 이전 길이를 씁니다.

2차 리뷰 때 요청하는 스크린샷은 1440×900 기준 기능 01·02·03, MCP, CTA 각 한 장과 375×812의 기능 02 패널·기능 03 엽서·MCP 세로 연결, 그리고 reduced-motion 상태의 MCP 한 장입니다.
