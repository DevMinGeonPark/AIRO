**0. 한 줄 총평**

기술적으로는 다 붙어 있지만, 화면이 "제품"이 아니라 "제품 목업을 올려둔 스톡 일러스트"처럼 보입니다. 원인은 세 가지입니다. 지도가 장소가 아니라 회색 선 패턴이고, AI는 13px 아이브로우 한 줄 말고는 어디에도 없으며, 116px 헤드라인과 9~11px UI가 한 화면에서 싸우고 있습니다. 리디자인의 핵심은 "문장 하나가 실제 교토 지도 위에 핀을 떨어뜨린다"는 인과를 첫 화면에서 보여주는 것입니다.

---

**1. 스크린샷 기반 비평 (영향 큰 순서)**

**1-1. 지도가 장소로 읽히지 않는다 (사실 + 판단)**
- 사실: `tailscale-explore.png`에서 1440px 폭 전체가 교토의 한 블록 정도입니다. 물은 굵은 청록 띠, 도로는 10~20px 흰 리본, 건물·공원·철도 구분이 없습니다. 지명 라벨은 활성 핀 하나에만 뜹니다. 경로는 1→2 구간에서 직각으로 꺾여 오류처럼 보입니다.
- 판단: 이 줌에서는 교토 사람도 어디인지 못 알아봅니다. "실제 지리 엔진"이라는 가장 큰 자산이 화면에서 증명되지 않습니다. 지도는 "인식 가능한 도시의 인쇄물"이어야 여행이 느껴집니다.

**1-2. AI가 보이지 않는다 (사실)**
- 사실: 인트로 화면에서 AI 신호는 13px 아이브로우와 스파클 아이콘뿐입니다. 헤드라인 "AI와 함께"는 단어일 뿐 행동이 없습니다. 탐색 화면의 채팅은 292px 패널 안 11px 텍스트로, 지도와 시각적으로 연결되지 않습니다.
- 판단: 방문자가 "지도 앱이네"까지는 이해하고 "AI가 뭘 해주는지"는 이해할 수 없습니다. 인과가 없기 때문입니다. 문장 → 답변 → 핀이 한 프레임에 있어야 합니다.

**1-3. 타이포 스케일 붕괴와 "애플 큰 글씨 + 3D 핀" 문제 (사실)**
- 사실: h1 116px, 자간 -0.075em. "함께."의 글리프가 붙어 있고 "로든"도 거의 닿습니다. 반면 hero-note 10px, 스크롤 라벨 10px, 코디네이트 10px, 도크 라벨 9px입니다. 비율 11.6배.
- 사실: 200px 광택 그라디언트 핀(`MaterialPin`)이 화면 중앙에 있고, 나머지 UI는 전부 플랫 알약 버튼과 1px 선입니다. 두 재질이 같은 화면에 있습니다.
- 판단: 이 조합이 사용자가 말한 "이상하고 싸구려" 느낌의 직접 원인입니다. 큰 글씨가 프리미엄을 만드는 게 아니라, 한 장면 안의 위계 일관성이 만듭니다.

**1-4. 탐색 화면의 UI 클러스터 과잉 (사실)**
- 사실: 1440 탐색 화면에 동시 노출되는 독립 UI 덩어리가 8개입니다. 탑바, KYOTO 라이브 헤딩, 인스펙터 카드, 위치 리드아웃, 도크, 어트리뷰션, 프로그레스 바, 모션 토글. 375에서는 지도 가시 영역이 세로 약 300px로 줄고, 3번 핀이 "은각사" 라벨과 겹칩니다.
- 판단: 대시보드를 축소해서 올린 모양이라 "화면 미리보기" 라벨 그대로 미리보기처럼 느껴집니다. 히어로는 앱을 다 보여주는 곳이 아니라 한 가지 인과를 보여주는 곳입니다.

**1-5. 팔레트 분열과 반복 카드 템플릿 (사실 + 판단)**
- 사실: 페이지는 따뜻한 #FAF7F2인데 지도 #ECEFE9, 패널 #F1F2EC, MCP 배경 #F0F1EB, 버블 #E2E8D9, 리드아웃 텍스트 #3C4C32·#53624B는 전부 차가운 세이지 계열입니다. 인스펙터 안 일러스트는 따뜻한 오렌지·갈색입니다.
- 사실: feature-1은 740×725 회색 패널 안에 채팅 3줄, 위아래 각 200px 공백. MCP는 허브-스포크 다이어그램. 두 섹션 모두 "둥근 회색 박스 안에 목업" 구조입니다.
- 판단: 화면 전체가 "회색 박스 3종 세트"로 읽히고, 브랜드의 따뜻함은 일러스트 안에만 갇혀 있습니다.

**2. 아트 디렉션: "종이 지도 위의 대화" (A Conversation on a Paper Map)**

한 문장 정의: 히어로는 카드도 기울기도 없이 뷰포트 전체가 교토의 따뜻한 지도 인쇄물이고, 그 위에 사용자의 문장 하나와 아이로의 답변이 놓이며, 답변의 결과로 핀이 떨어지고 경로가 그려진다. 스크롤은 "하루"의 단위다.

방문자가 여행 + AI로 이해하는 이유는 세 신호가 한 장면에 있기 때문입니다. 첫째, 가모가와 강과 히가시야마 산자락, 한국어 지명(니시키 시장, 철학의 길, 아라시야마)이 보이는 인식 가능한 도시 지도는 여행입니다. 둘째, 사람의 문장과 아이로의 답변 카드가 핀에 리더선으로 붙어 있고, 답변 직후 핀이 떨어지는 것은 AI입니다. 셋째, 카메라가 움직일 때 좌표 숫자가 실시간으로 바뀌는 것은 "진짜 지리"입니다.

**3. 스크롤·클릭 스토리보드**

히어로 핀 길이는 `+=300vh`(하루당 100vh). 진행도 p로 페이즈 결정.

**Beat 0 · 로드 (0~1.6s, 스크롤 무관)**
- 원인: 페이지 진입. 결과: 지도가 scale .985→1, opacity 0→1로 0.8s 안착. 헤드라인 글자 스태거(기존 GSAP 유지).
- 0.5s: 카드에 사용자 문장이 타이핑됨(기존 Conversation 타이머 재사용). 1.1s: 아이로 답변 표시. 1.2s부터 핀 3개가 120ms 간격으로 드롭(translateY -28→0, scale .6→1, opacity 0→1, transform-origin 50% 100%). 마지막 핀 착지와 동시에 경로 SVG가 900ms 동안 그려짐(stroke-dashoffset, 유일한 비-transform 애니메이션). 리드아웃 숫자가 은각사 좌표로 틱.
- 의미: "문장을 말하니 핀이 생겼다."

**Beat 1 · 둘째 날 (p 0→0.33)**
- 원인: 스크롤. 결과: p 0~0.12에서 헤드라인·설명·CTA가 y -40, opacity 0으로 물러남(지도를 비워줌). Day 세그먼트가 Day 2로 이동. 카메라가 북동(은각사)에서 중심(니시키 시장→폰토초→기온)으로 팬. 이동 거리 약 3km이므로 화면상 700px 이상 움직여 "지도가 움직인다"가 몸으로 느껴집니다. 리드아웃 숫자가 연속으로 틱.
- Day 1 경로는 --trace로 남고 핀은 24px 회색으로 축소. Day 2 카드 내용으로 교체(문장 → 답변 → 핀 드롭 → 경로, Beat 0과 동일 시퀀스를 p 0.2~0.33 구간에 스크럽으로 재생).
- 의미: "하루를 스크롤하면 다음 날이 그려진다."

**Beat 2 · 셋째 날 (p 0.33→0.66)**
- 원인: 스크롤. 결과: 카메라가 서쪽 아라시야마로 약 8km 팬. 이동 중 카메라 scale 1→.8→1(돌리 아웃·인)로 거리감을 만들고, 가쓰라 강과 대나무 숲 --park 덩어리가 프레임에 들어옵니다. Day 3 시퀀스 재생. Day 1·2 흔적이 프레임 밖으로 밀려나며 여행이 도시 규모라는 게 드러남.
- 의미: "사흘이 도시 하나를 가로지른다."

**Beat 3 · 전체 (p 0.66→1)**
- 원인: 스크롤. 결과: 카메라가 세 날을 모두 담는 스케일(약 .55)로 줌 아웃. 세 경로가 한 여행으로 보임. 카드가 하단 중앙 요약 알약 `.hero-summary`로 접힘: "느긋하게, 교토 · 3일 · 9곳" 14px + 옆에 프라이머리 "여행 시작하기" 재등장. p=1에서 핀 해제, 기능 섹션 진입.
- 의미: "이게 완성된 여행이고, 여기서 시작하면 된다."

**클릭**
- Day 세그먼트 클릭: 기존 `navigate` 로직으로 `scene.start + (i/3)*(end-start)`에 lenis.scrollTo. 스크롤과 같은 결과를 클릭이 만듭니다.
- 핀 클릭: 카드가 그 핀으로 재앵커(카드 컨테이너 transform 변경). 카드 마지막 줄이 그 정류지 정보로 교체.
- "지도 조작" 토글(Day 세그먼트 왼쪽 36px 아이콘 버튼): 기존 `interactive` + `onInteract → manual` 활성. 드래그·줌·핀 드롭(기존 data-placing) 허용, 스크럽 정지. 다시 누르면 현재 Day 프레임으로 복귀. 기존 전체화면 탐색 모드(`data-exploring`)는 폐기하고 이 토글이 대체합니다.

**4. 기능 / MCP / CTA 변경**

원칙: 세 기능은 각각 다른 구도를 갖고, 페이지 배경 위에 직접 놓입니다. 회색 패널은 0개.

- **기능 01 · 떠오르는 대로 말해요**: 오른쪽 패널 제거. 대화 스레드를 페이지 배경 위에 직접 놓습니다. 왼쪽 1px 세로 타임라인(--ink @ 15%)에 3턴(사용자/아이로/사용자)이 매달리고, 각 버블은 스크롤 리빌. 스레드 끝에 320×200 앰비언트 `JourneyMap`(비인터랙티브, 반경 12px)이 붙어 마지막 답변의 핀이 떨어집니다. 히어로의 인과를 축소 반복. 버블 텍스트 16px, 사용자 버블은 --built 배경, 아이로는 흰색.
- **기능 02 · 일정과 지도**: 유일한 컨테이너지만 카드가 아니라 전폭 밴드입니다. 높이 560px, 좌우 여백 0, 같은 종이 지도 스타일. 왼쪽 gutter 위치에 폭 360px 흰 카드(기존 `.route-itinerary` 재사용)가 지도 위에 얹혀 Day 탭 + 정류지 리스트(14px)를 보여주고, 탭 전환 시 지도 카메라가 팬합니다. 카피는 밴드 위쪽 텍스트 블록으로 이동.
- **기능 03 · 여행 자료**: 기존 `/public/gen/` 일러스트 3장을 엽서 스택으로. 각 240×300px, 반경 12px, 기존 `DAYS.rotation` 값으로 살짝 회전, 8px 흰 테두리(사진 인화지 느낌), 아래 12px mono 캡션. 패널 없이 배경 위에 놓고 스크롤 시 부채꼴로 펼쳐짐(transform만). 이 섹션이 페이지의 유일한 "따뜻한 그림" 자리라 대비가 생깁니다.
- **기능 헤딩**: h2 72px→56px / 600 / -0.025em. 아이브로우 영문 "A LITTLE HELP…" 유지하되 11px mono tracking .12em.
- **MCP**: 허브-스포크 제거. "같은 여행, 두 창" 구도. 왼쪽 480px에 외부 AI 도구 창(윈도우 크롬 없이 1px 보더 + 상단에 Claude · Codex · Cursor · ChatGPT 텍스트 탭, 기존 aria-pressed 로직 재사용)에 문장 "교토 둘째 날에 카페 하나 더 넣어줘". 오른쪽 480px에 아이로 일정 카드(기능 02 카드와 동일 컴포넌트), 새 정류지 행이 오렌지 하이라이트로 삽입됨. 두 창 사이 120px 간격에 1px 오렌지 연결선과 이동하는 6px 점(transform). 탭 클릭 시 왼쪽 창 제목만 바뀜. 배경은 페이지 색 그대로, 위아래 1px --ink @ 10% 룰과 160px 패딩으로 구분. 캡션 "Claude와 연결되는 내 여행" 유지.

**6. 2차 리뷰 시각 승인 기준**

요청 스크린샷: 1440×900에서 p=0, 0.33, 0.66, 1.0 네 장. 375×812에서 Day 1, Day 3 두 장. 768×1024 p=0 한 장. 1440×900 reduced-motion 한 장. 기능 01·02·03, MCP, CTA 각 1440 한 장.

아래 중 하나라도 실패하면 반려합니다.

- 히어로 지도가 뷰포트 100%를 채우고 기울기·라운드·프레임 그림자가 없다.
- 1440 p=0 프레임에서 가모가와 강과 히가시야마 --park 워시가 식별된다. 한국어 지명 라벨 3개 이상 보인다.
- p=0과 p=0.66 스크린샷의 리드아웃 경도가 0.03° 이상 다르다. 카메라 이동이 실제로 일어났다는 증거.
- 히어로 동시 노출 UI 클러스터가 5개 이하다. 탑바·인스펙터·도크가 없다.
- h1 72px, 자간 -0.025em 이내, 글리프 충돌 없음. 히어로 내 12px 미만 텍스트는 어트리뷰션뿐이다.
- 광택·그라디언트 핀이 없다. 핀은 단색 플랫 36px 이상, 숫자가 읽힌다.
- 경로 꺾임이 round join으로 부드럽고, 1440에서 두께 4px. 지난 날 경로가 옅게 남아 있다(p=0.33 이후).
- 카드가 활성 핀 옆에 리더선으로 붙어 있고, 사용자 문장과 아이로 답변이 15px로 읽힌다.
- p=1.0에서 세 날 경로가 한 프레임에 들어오고 요약 알약과 CTA가 보인다.
- 375 Day 1: 핀·라벨·카드 간 겹침 없음. 지도 가시 영역 세로 240px 이상. CTA가 첫 화면에 보인다.
- 페이지 어디에도 #ECEFE9·#F0F1EB·#F1F2EC·#E2E8D9 계열 세이지 면이 남아 있지 않다. 세이지는 공원·물 레이어에만.
- 기능 01에 컨테이너 패널이 없고 스레드 끝에 작은 지도가 있다. 기능 02는 전폭 밴드다. 기능 03은 엽서 3장이 패널 없이 놓여 있다.
- MCP에 원형 허브 다이어그램이 없고, 왼쪽 도구 창과 오른쪽 일정 카드 사이 연결선 하나만 있다.
- CTA 배경 지도가 opacity .4 이하이고 엽서 일러스트가 우하단 한 장이다.
- reduced-motion 스크린샷이 p=1.0 구도(전체 줌 아웃)와 같고 Day 1 카드가 보인다.
- 카피·링크·라우트·섹션 순서가 현재와 동일하다.

한 가지 미리 밝혀둘 리스크가 있습니다. 엔진이 레이어별 클래스를 노출하지 않으면 팔레트 기준(강·공원 식별)을 만족할 수 없으니, 구현 전에 Codex가 그 부분을 먼저 확인해 주면 좋겠습니다. KYRO·Chartogne-Taillet 리서치 증거가 오면 이 방향의 Beat 1~3 카메라 연출과 카드 앵커 방식만 조정할 예정이고, 방향 자체를 바꿀 계획은 없습니다.
