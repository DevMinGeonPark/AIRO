# 여행 일정 진행 체크

출국 전날 Todo는 Day 0·Day 1에서 같은 목록을 연다. 일정이 없는 날도 두 날짜는 표시한다. 준비물과 QR 이미지·Visit Japan Web 링크를 그대로 공유한다.

일정 목록의 원형 버튼 또는 장소 상세의 완료 버튼으로 진행 여부를 저장한다. 장소 상세에서 직접 체크, 위치로 자동 체크, 시간으로 자동 체크, 위치 또는 시간을 고른다. 자동 체크는 사용자가 장소별로 설정한다. 완료 시각과 체크 방법을 표시하고 현재 표시 중인 일정의 완료 개수를 합산한다.

- 시간: 여행 시작일, 장소의 Day와 HH:mm, 일정 시간대를 기준으로 실제 오늘의 시간이 지난 장소를 체크한다. 기본 시간대는 Asia/Seoul이며 일정 목록의 자동 체크 설정에서 바꾼다.
- 위치: 위치 자동 체크 시작을 누르면 브라우저 권한을 요청한다. 기본 반경 150m, 선택 범위 100–1000m. 최신 60초 이내 표본이며 오차가 100m 이하이고 `장소까지 거리 + 오차 <= 반경`이어야 한다.
- 자동 체크는 여행 화면이 보이는 동안 동작한다. 화면을 다시 열면 오늘의 시간 조건을 확인한다. 숨겨진 화면에서는 위치 추적을 중지하며, 새로고침 후 위치 자동 체크는 다시 시작해야 한다.
- 직접 체크 해제한 일정은 자동 체크에서 제외한다. 장소 상세의 `체크 초기화·자동 체크 다시 허용`으로 해제할 수 있다. 미래·과거 날짜의 미완료 일정을 자동으로 일괄 완료하지 않는다.

GET/PATCH `/api/trips/[tripId]/progress`는 계정 인증과 여행 소유권을 확인한다. `0014_itinerary_progress.sql`의 `mutate_trip_progress` RPC가 시간과 위치 조건을 다시 검증하고 archive의 `itineraryProgress`만 수정한다. GPS 표본은 판단에 사용하고 저장하지 않는다. 변경이 없으면 revision·변경 이력을 늘리지 않는다. 버전 충돌은 409로 반환하고 최신 값을 다시 읽는다. 완료 상태와 규칙은 여행 내보내기·가져오기 및 변경 이력 되돌리기에 포함된다.

검증은 외부 서비스 없이 진행한다. `test-mcp-local.mjs`/`check-itinerary-progress.mjs`는 날짜·시간대·GPS 오차·오래된 표본·직접 해제·충돌·소유권·이력 복원을 PostgreSQL에서 검사한다. `test-workspace-ui.mjs`는 Chrome 1440/390·WebKit 320에서 Day 1 Todo, 저장 실패, 새로고침 복원, 시간 자동 완료, 위치 권한 거부/정밀도/완료/중지와 기존 PDF·QR 모달을 검사한다. 위치 자동 완료는 모의 GPS로 검증한다.
