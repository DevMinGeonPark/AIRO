현재 배포: **0.3.8 / code 11**. [현재 위치 버튼 검증](CURRENT_LOCATION.md)을 우선 참고한다. [선택형 일정·경로·MCP](STOP_CHOICES.md)도 유지한다. [즉시 체크·시간/GPS·완료 경로 제외](ANDROID_PROGRESS_RESPONSE.md)도 유지한다. 아래 이전 버전 기록은 유지한다.

대상: [AIRO Cloud 0.3.2](https://airo.dev-heptivision.com/downloads/airo-android-cloud-0.3.2.apk), 운영 서버 `https://airo.dev-heptivision.com`.

0.3.1에는 **내 정보 → 설정 → 앱 업데이트**가 추가됐다. 0.3.0 이하 사용자는 이 APK를 한 번 직접 설치한다. 기존 앱을 삭제하지 않고 업데이트해야 로컬 로그인과 자료가 유지된다. [업데이트 흐름과 배포 방법](ANDROID_UPDATES.md)을 참고한다.

0.3.0의 지도·PDF·예약·예산·변경 이력·자료를 활용하는 AI 대화·외부 공유를 실제 계정과 휴대폰에서 확인한다. 자동 검사는 가짜 Auth·임시 DB와 전용 에뮬레이터를 사용했으며, 실제 로그인 제공자·사용자 PC 구독 세션의 확인을 대신하지 않는다.

0.3.2 추가 확인: 여행을 열자마자 도로 선이 보이는지, Day 선택/이전·다음/스와이프와 왼쪽 패널, 장소 선택 후 지도 위 카드, 상세 일정의 경로 따라가기, 웹↔앱 완료 체크 공유, Day 0 Todo 저장, 저장 QR 이미지 확대를 확인한다. 위치 자동 체크는 시작 버튼에서만 권한을 요청하며, 해당 날짜·범위 안에서 정확한 위치가 잡힐 때 체크되는지와 앱을 벗어나면 위치 수집이 멈추는지 실제 기기에서 확인한다. [자동 검증 범위](ANDROID_WEB_PARITY.md).

0.3.3 추가 확인: Day 접기·펼치기와 전체 일정 복귀, 복사 아이콘의 현지명, Day 0/1 Todo 패널↔확대 전환 및 저장, 설치된 Trip.com/Agoda 앱으로 예약 링크 열기와 미설치 웹 전환, 삼성월렛 열기, 캘린더에 채워진 날짜·시간·장소 확인, 사진 선택→재실행 후 유지→연결 해제를 확인한다. 사진은 이 기기에만 연결되고 연결 해제 후 원본은 남아야 한다.

0.3.4 추가 확인: Day 완료 숫자 옆 설정에서 ‘위치 또는 시간’을 적용하고 기기 위치 권한을 허용한다. 해당 날짜/시간대의 예정 시간 또는 도착 반경 조건에서 자동 완료되는지 확인한다. 느린 네트워크에서 연속 체크/취소→즉시 숫자·핀·경로 변경→저장 완료, 실패 시 복원, 중간 장소 완료 후 남은 장소 사이 경로 재계산을 확인한다. 직접 해제한 장소는 자동으로 다시 체크되지 않아야 한다.

2026-09-18 앱 E2E에 필요한 서버·인증·이메일 설정을 완료했다. SMTP 저장 후 운영 인증 사전 검사 7개가 모두 통과했다. 실제 사용자 로그인·메일 수신·기기 복귀는 아래 E2E에서 확인한다. 실제 메일 발송과 유료 API 호출은 실행하지 않았다. 발신자는 `AIRO <login@auth.airo.dev-heptivision.com>`이며, 같은 사용자에게 로그인 메일을 다시 요청하는 간격은 60초다.

## 실제 계정·기기에서 확인할 순서

1. Cloud APK를 설치하고 서버 주소가 운영 주소인지 확인한다. Google 로그인 → 앱 복귀 → 내 여행 화면을 확인한다.
2. 로그아웃 후 이메일 로그인을 시작한다. 해당 휴대폰에서 새 메일의 링크를 열고 앱 복귀와 계정 표시를 확인한다.
3. 로그인 취소 후 재시도, 다른 기기에서 시작한 링크 거부, 만료된 링크 거부를 확인한다. 성공 후 앱을 완전히 종료·재실행해 세션 유지도 확인한다.
4. 테스트 여행을 만들고 이름·일정·날짜·장소·순서를 바꾼다. 웹의 같은 계정에서 변경을 확인한다. 가까운 날짜 선택, 날짜 카드 좌우 이동, 지도 드래그, 빈 지도 탭으로 조작부 숨김/표시와 뒤로 가기 후 선택 유지도 확인한다.
5. 장소 검색·저장·즐겨찾기·일정 추가, 지도 핀과 실제 도로 경로를 확인한다. 비행 구간을 도보 선으로 표시하지 않아야 한다.
6. **여행 자료 → PDF 추가**에서 2MB 이하 PDF를 선택한다. 앱 내부 원본 미리보기·페이지·확대 후 날짜/장소에 연결하고 저장한다. 해당 장소에서 같은 PDF를 열고, 재첨부 시 중복되지 않는지 확인한다. PDF 앱 설치는 필요 없다.
7. 예약 이름·HTTPS 링크·예약 번호·예약/결제 상태와 관련 PDF·장소를 저장한다. 웹과 앱에서 같은 예약을 수정해 revision 충돌 시 작성 내용이 남는지 확인한다. 메모 문구만으로 확정 상태를 표시하지 않아야 한다.
8. 예약의 **예산 연결**에서 금액을 확인해 새 지출을 추가하거나 기존 지출을 연결한다. 다시 진입하면 같은 지출을 수정하며 중복 생성되지 않아야 한다. 웹 예산 편집 후에도 예약 연결이 유지돼야 한다.
9. 여행 메뉴의 **변경 이력**에서 변경 전후를 읽고, 테스트 예약 변경 한 건만 되돌린다. 다른 화면에서 먼저 수정한 경우 충돌이 표시되는지 확인한다.
10. 파일 앱의 PDF 또는 브라우저의 예약 HTTPS 링크를 AIRO로 공유한다. 여행 선택→미리보기/예약 초안→검토 후 저장을 확인한다. 로그아웃 상태로 공유한 뒤 로그인해 이어가기도 확인한다.
11. 여행 JSON 내보내기·다시 가져오기 후 PDF 원본·해시·날짜/장소 연결·예약·예산 연결과 중복 가져오기 방지가 유지되는지 확인한다.
12. 본인 PC의 Codex **구독** 기기를 연결하고, 장소 또는 문서에서 **AI에 활용**을 선택해 요청한다. 선택 자료 표시·도구 결과·관련 화면 복귀·중지·재시도를 확인한다. API 계정이나 별도 유료 fallback을 사용하지 않는다.
13. 앱을 완전히 종료·재실행하고 자료와 세션을 확인한다. 로그아웃 후 다른 계정에서 이전 여행·문서·공유 초안이 보이지 않는지 확인한다. 테스트 자료를 만든 계정에서 해당 자료만 정리한다.
14. **내 정보 → 설정 → 앱 업데이트 → 업데이트 확인**을 누른다. 현재 최신 배포는 ‘최신 버전을 사용하고 있어요’가 보여야 한다. 다음 버전이 배포되면 변경 내용·파일 크기 확인 → 다운로드(취소/재시도 가능) → 지금 설치 → 필요한 경우 Android의 ‘이 출처 허용’ → 돌아와 지금 설치 → Android 설치 승인 순서로 진행한다. 앱 재실행 후 새 버전·로그인·기존 여행이 유지되는지 확인한다.

각 항목에 기기/OS·계정 구분·결과·실패 시 화면과 시각을 기록한다. 비밀번호·로그인 토큰·문서의 실제 개인정보는 결과 기록에 넣지 않는다. 정식 스토어 서명·심사는 이 검증용 APK의 E2E 범위와 별도다.
