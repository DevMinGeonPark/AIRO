# QR·이미지 자료

Day 0·Day 1의 Todo 상단과 자료·맛집의 `QR·이미지 자료`에서 저장한 원본 이미지를 연다. 처음에는 모달로 열리며 확대/화면 맞춤, 크게 보기, 이미지 저장, 원본 사이트 열기를 지원한다. Todo 안에서 뷰어를 닫으면 Todo로 돌아간다. Visit Japan Web의 QR 화면 주소는 `https://www.vjw.digital.go.jp/main/#/vjwpic026`이며 로그인 후 여행 선택이 필요할 수 있다.

이미지는 여행 소유자만 접근할 수 있는 `trip_archives.data.images`에 저장한다. GET `/api/trips/[tripId]/images`는 메타데이터만 반환한다. 원본은 모달을 열 때 GET `/api/trips/[tripId]/images/[sha256]`로 불러오며 `?download=1`은 첨부 다운로드다. 두 경로 모두 계정 인증·여행 소유권을 확인하고 `private, no-store`로 응답한다. 이미지 원본을 공개 경로, 썸네일 서비스, 외부 처리 서비스로 전송하지 않는다.

POST `/api/trips/[tripId]/images`는 이름, PNG/JPEG base64 원본, HTTPS 출처 URL, 캡처 시각을 받는다. 서버가 디코딩과 해시를 확인하며 재인코딩하지 않는다. 최대 2 MiB·4096×4096·10개, 기존 보관 자료 전체 제한은 8 MiB다. 동일 원본 재전송은 중복 첨부하지 않는다. 서버 원본 저장 API만 추가했으며 일반 파일 업로드 화면과 새 MCP 도구는 추가하지 않았다.

`0013_trip_images.sql`의 첨부 RPC는 소유권과 편집 권한을 확인하고 여행/자료 행을 잠근 뒤 이미지만 추가한다. 기존 PDF·예약·Todo를 보존한다. 변경 이력은 이미지 메타데이터만 노출하며 기존 되돌리기 기능으로 복원할 수 있다. 전체 여행 내보내기·가져오기에 원본도 포함된다.

이미지는 캡처 당시 자료다. Visit Japan Web 등록 내용을 수정한 경우 새 QR을 다시 저장해야 한다. 생성·재발급·신고 제출이나 Visit Japan Web 계정 정보 저장을 자동 실행하지 않는다.

검증: 합성 이미지로 Chrome 1440/390·WebKit 320의 모달, 실제 픽셀 로드, 확대, 전체 크기, 다운로드 링크, 원본 URL, 오류 재시도, 중첩 모달 Escape/포커스 복귀를 확인했다. 실제 QR은 운영 인증 화면에서 원본 SHA-256 일치·300×300 렌더링·기존 Todo 유지·미인증 401만 확인했으며 공개 테스트 산출물에는 넣지 않았다. 로컬 PostgreSQL에서 소유권·읽기 전용 권한·메타데이터 분리·이력 복원·중복 방지·잘못된 형식 거절을 검증했다.
