# Android 0.3.5 — 즉시 체크·완료 경로 제외

2026-09-18, versionCode 8. 기존 0.3.3/0.3.4 위에 설치하는 같은 개발 서명 APK. 서버 API·DB 변경 없음.

## 동작

- 직접 체크와 자동 판정 결과를 서버 응답 전에 화면에 반영한다. 완료 숫자·체크 아이콘·지도 핀·남은 경로가 같은 상태를 사용한다.
- 저장 중에도 다른 장소 체크와 체크 취소를 받는다. 저장 요청은 서버 revision 순서대로 보내며 아직 보내지 않은 동일 항목의 변경은 마지막 의도로 합친다. 0.3.5에서는 즉시 완료되는 저장 뒤 자동 판정이 이어져도 저장 worker가 중복 시작되지 않도록 보완했다.
- 409 충돌이면 최신 상태 위에 대기 중인 변경을 다시 적용하고 제한된 횟수로 재시도한다. 실패 시 서버를 다시 읽어 응답 유실 여부를 확인하고 실패한 변경만 되돌린다. 뒤에 입력한 다른 장소의 체크는 유지한다.
- 완료한 장소는 지도에 초록 체크로 남으며 확산 효과를 재생한다. 목록 체크도 짧게 확대·색상 전환한다. Android 애니메이션 비활성 설정과 화면 일시중지를 존중한다.
- 완료 장소는 남은 도로 경로·항공 곡선·경로 따라가기의 경유지에서 즉시 제외한다. 가운데 장소를 체크하면 앞뒤 미완료 장소 사이 경로를 다시 계산한다. 체크를 취소하면 다시 포함하며 이전 도로 캐시를 재사용한다. 체크는 여행 장소 자체를 삭제하지 않는다.
- Day 완료 숫자 옆 설정 아이콘에서 현재 표시한 일정 전체에 직접/시간/GPS/위치 또는 시간 규칙을 적용한다. 시간이 없는 장소는 ‘위치 또는 시간’에서 GPS 규칙을 사용한다. 장소별 도착 범위·규칙도 변경할 수 있다.
- 자동 판정은 여행 날짜와 선택한 시간대를 기준으로 오늘 일정에만 적용한다. 시간 조건은 1초마다 확인한다. GPS는 전경에서 3초 간격으로 요청하고 마지막 위치도 신선도·정확도를 통과할 때만 사용한다. 60초 이내, 오차 100m 이하, `거리 + 오차 <= 설정 반경`이어야 한다. 서버도 같은 조건을 다시 검사한다.
- 위치 기능은 설정 적용/위치 자동 체크 시작에서만 권한을 요청한다. 앱을 벗어나면 위치 수신과 자동 판정이 멈춘다. 직접 해제한 일정은 자동 판정보다 우선하며 초기화 전에는 자동으로 다시 완료하지 않는다.

‘남은 경로’는 미완료 일정 장소 사이 경로다. 현재 GPS에서 다음 장소까지 실시간 길 안내를 새로 시작하는 기능은 아니다. 과거·미래 날짜를 임의로 자동 완료하거나 위성 위치를 백그라운드에서 상시 추적하지 않는다.

## 검증

증거 폴더: `.private/deployment/android-progress-20260918/`.

- 지연 응답 중 즉시 체크/취소/연속 입력, 입력 합치기, 실패한 장소만 복원, 다른 기기의 revision 변경, 저장 성공 후 응답 유실 복구를 단위 검사한다.
- 날짜·시간대·오래된 GPS·정확도·수동 해제 우선순위와 시간 없는 장소의 GPS 설정을 검사한다.
- 완료한 가운데 장소의 경로/재생 제외, 체크 취소 시 캐시 복원, 전체 완료 시 경로가 없어지는 것을 검사한다.
- 전용 Android 16 에뮬레이터에서 실제 MapLibre 소스/렌더 경로와 체크 핀, 완료 pulse를 검사한다. 서버 응답을 막아둔 동안 경로 2개→1개→0개와 취소 시 복원을 확인한다.
- Android LocationManager의 모의 GPS provider를 통해 실제 위치 listener→판정→완료 핀/경로 제외→저장 흐름과 시간 자동 완료를 확인한다. 실제 위성 GPS/현장 오차 검증과는 구분한다.
- 테스트는 합성 일정과 로컬 저장소만 사용한다. 별도 과금 API, 실제 여행 데이터 쓰기, AI 호출 없음.

0.3.5 최종 검사: Cloud/Demo JVM 각각 49건 통과. Lint 오류 0, 경고 각 39건. Android UI 390dp 6건 통과. 저장 응답이 즉시/지연으로 섞일 때 worker가 하나만 실행되는 회귀 검사를 추가했다. 결과는 `release-035/verification.json`, `release-035/ui-final-390dp.log`, 화면은 `release-035/screens/`의 `(2)` 파일에 있다.

0.3.4에서 같은 화면 구현의 390dp 6건, 320dp/글꼴 150% 4건, 1024dp 4건을 통과했다. 작은 화면과 태블릿에서도 Day 설정 일괄 적용, 기존 Todo 저장/확대/축소/Day 1 재조회와 지도 조작을 함께 확인했다. 이 기록은 루트의 `verification.json`, `ui-final-*.log`, `final-screens/`에 그대로 보존했다. 0.3.5에서는 worker 시작 순서와 버전만 수정했으며 작은 화면/태블릿 검사를 중복 실행하지 않았다.

## 같은 날 웹 UI 변경 검토

작업 중 웹 Day 접기·패널 안 Todo·전체 일정 복귀·현지명 한 줄·예약 앱 링크·캘린더·기기 사진 변경을 감지하고 코드를 비교했다. Android는 0.3.3부터 해당 기능을 네이티브로 제공한다. 캘린더는 ICS 다운로드 대신 작성 Intent, 사진은 IndexedDB 복제 대신 선택 URI 접근, 삼성월렛은 설치 앱 열기를 쓴다. 복사는 사용자 요청대로 문구 없이 아이콘만 유지한다. 변경 이력·자료/예약 관리 진입도 앱에 이미 있다. 비교한 소스 27개를 기준 파일에 기록했다. 웹 코드 자체는 이번 Android 작업에서 수정하거나 배포하지 않았다.

웹의 마지막 복사 상태 안내·타이머 정리와 사진 저장의 Blob→ArrayBuffer 변경도 검토했다. 네이티브 복사는 기존 아이콘과 Android 클립보드 안내를 유지하고, 사진은 암호화된 선택 URI 연결을 사용하므로 브라우저 저장 형식 변경은 적용 대상이 아니다.
