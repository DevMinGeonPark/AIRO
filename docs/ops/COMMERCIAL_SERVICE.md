# 별도 여행 서비스의 계정형 AIRO 전환

**범위 해석 정정:** 아래 기능 작업 후 사용자가 기존 일정을 자신의 AIRO 계정에 등록해 달라는 뜻임을 명확히 했다. 추가 기능 구현은 중단했다. 현재 작업은 `UNIFICATION.md`의 계정 일정 등록이며, 아래는 이미 진행된 변경의 기록이다.

2026-09-10 사용자가 범위를 정정했다. 개인 여행 한 건을 특정 계정에 가져오는 작업이 아니라, 기존 `../AIRO` 서비스의 기능을 여러 사용자가 자기 계정으로 이용하는 AIRO 서비스로 옮긴다. 원본 서비스와 개인 자료는 보존하며 자동으로 가져오지 않는다. 이번 변경은 기능 통합이며 결제는 포함하지 않는다.

## 구현한 기능

- 로그인한 사용자의 여행별 일정·지도·채팅과 MCP 편집 동기화.
- 실제 도로 좌표를 따르는 이동 재생. 항공은 지도와 같은 곡선이며, 도로 조회 실패 시 직선으로 대체하지 않는다. 수동 정지·일정 변경·탭 숨김·모션 줄이기를 처리한다.
- 모바일 지도 위에서 접기·반 펼치기·펼치기 및 드래그가 가능한 일정 시트. 검색·직접 편집·채팅 전환과 선택 장소의 지도 여백을 조정한다.
- 현재 지도 주변의 맛집·카페·숙소 검색, 일정 추가, 계정 여행에 장소 즐겨찾기 저장. 저장 실패 시 결과와 입력을 보존한다.
- 개인 자료를 가져오지 않은 새 여행에서도 예산을 작성·수정·삭제할 수 있다. 통화·직접 입력하는 계산용 환율·일차·결제 상태·예비비를 지원한다. 여러 창의 충돌을 감지하고 최신 자료를 불러와도 작성 중인 항목은 유지한다.
- 예산·장소를 기존 여행 자료 JSON의 해당 필드에만 저장한다. 사진·도로·문서·원본 예산을 보존하고 전체 내보내기와 다시 가져오기에도 포함한다.
- 준비되지 않은 MCP API 키를 발급하지 않도록 막는다. 서버 서명 설정이 없는 환경은 OAuth 로그인 연결을 안내한다.

## 데이터베이스

Supabase `airo` 프로젝트(`colczqltsfzqgzsnnqvc`)에 다음 추가 마이그레이션을 적용했다. 초기 테이블이나 기존 여행 자료를 다시 만들지 않았다.

1. `0006_mcp_itinerary.sql`: 공통 일정 변경과 중복 요청 처리.
2. `0007_mcp_authorization.sql`: MCP 권한·연결·요청 한도와 토큰 훅.
3. `0008_trip_budget.sql`: 예산 버전 충돌 처리와 장소 즐겨찾기의 원자적 저장.

`update_trip_budget`와 `save_trip_place`는 인증된 소유자의 RLS를 사용한다. 익명 호출은 허용하지 않는다. 예산과 장소는 같은 여행 자료 행을 잠그고 해당 JSON 필드만 수정한다.

## 확인한 범위

- `npm run test:workspace`: 메모리 PostgreSQL의 전체 마이그레이션, 계정 격리, 예산 충돌·검증·자료 보존, 장소 중복 저장, 경로 보간 검사. 실제 Chrome 1440/390px와 WebKit 320px에서 실제 컴포넌트의 재생·정지·시트 드래그·검색·저장·실패·재시도·예산 편집 검사. 브라우저 테스트의 API 응답은 가정 데이터다.
- `npm run test:archive`: 기존 개인 자료 전체 필드와 PDF 해시, 가져오기 검증.
- `npm run test:mcp:local`, `node scripts/test-mcp-ui.mjs`: MCP 계약·권한·일정 순서와 화면 동기화 회귀 검사.
- 운영 Supabase의 임시 트랜잭션에서 실제 일정 RPC·예산 충돌·장소 중복 방지·자료 보존·계정 격리를 확인하고 전부 롤백했다. 테스트 계정과 여행은 남기지 않는다.
- Production build, TypeScript, 변경 파일 ESLint, 로그인 화면과 인증 없는 예산 API의 401, 계정 페이지의 로그인 이동을 확인했다.

결과: `assets/validation/workspace/`, `assets/validation/mcp/`. 배포 주소와 빌드 전환 상태는 `DEPLOYMENT.md`, 실제 Google 및 MCP 인증 설정은 `AUTH_SETUP.md`, `MCP_SETUP.md`에 기록한다. 외부 AI 도구에서 실제 사용자 로그인·여행 권한 승인을 거친 토큰 발급은 별도 확인이 필요하다.
